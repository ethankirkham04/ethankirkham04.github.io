Before taking this course, I had never used TypeScript before. Most of my programming experience came from Python, C, and C++. Python is still the language that feels the most natural to me, so getting used to TypeScript took some time. Since I already had experience with programming, learning TypeScript was not completely overwhelming. It was mostly about understanding the new syntax and getting used to the way TypeScript handles different types of data.

## Learning TypeScript

So far, I have had a good experience with TypeScript. Some parts feel familiar because of my experience with other programming languages, while other parts are still new to me. One of the biggest differences I noticed is how much TypeScript focuses on types. At first, I thought this made programming more complicated, but I started to understand how it can help catch mistakes before the program even runs.

I also learned more about ES6 through this module. I practiced things like arrow functions, classes, destructuring, template literals, imports, exports, and promises. Some of these concepts were confusing at first, but after using them more, they started to feel more natural.

From a software engineering perspective, I think TypeScript is useful because it gives code more structure. I can see how this would help when working on larger projects or working with other developers. Even though I am still more comfortable with Python, I feel a lot more comfortable with TypeScript now than I did at the beginning.

## Practicing via WODs

I also think the Workout of the Day exercises have been useful. I like that the WODs give me a problem to solve and a target time to work toward. Since I usually take my time when programming, having a timer pushes me to think and make decisions faster.

The timed part can be stressful, especially when I get stuck on a small problem and know the clock is still running. At the same time, I can see how the WODs help me figure out what I understand and what I still need to practice.

The idea of athletic software engineering makes sense to me because programming gets easier with repetition. The more I practice similar problems, the faster I start recognizing what I need to do. For me, becoming faster at programming is not just about typing code quickly. It is about understanding the problem well enough that I can make better decisions without having to think through every small step.

I think this style of learning will work for me as long as I focus on understanding the code first and speed second. As I continue practicing, I think the things that seemed confusing at the beginning will become more natural.
